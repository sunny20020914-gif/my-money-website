# 旧URL → 新URL 対応表（案）

GSC「検索パフォーマンス」過去3か月（2026-06-19〜09-19）と、
公開中の `/industries` に載っている**現行35業界**を突き合わせて作成。

コードはまだ変更していません。この対応が妥当かを確認してください。

---

## 被害の規模

| | 本数 | クリック | 表示 |
|---|---:|---:|---:|
| **死んでいるURL** | **25** | **17** | 175 |
| 生きている業界URL | 33 | 12 | 312 |

サイト全体は98クリック。**死にURLが17%を占めています。**

注目すべきは、**死んだURL（25本・17クリック）のほうが、生きているURL（33本・12クリック）よりクリックを稼いでいる**こと。
旧名のほうが検索語に近かったためで、これは後述の「表記」の論点につながります。

## 表記についての論点（重要）

301を入れてもURLは復活しますが、**着地するページの見出しは「製薬・バイオ」になります。**

旧URLが強かったのは、`製薬` `証券` `半導体` といった**短い語が検索語と一致していた**からです。
実際、死んだ25本のほうが生きている33本よりクリックが多いという逆転が起きています。

リダイレクトだけでは 6.0位 は戻らない可能性があります。
各業界ページの title / h1 に、統合前の呼び名も含める対応を併せて検討すべきです。

例：`製薬・バイオ業界の初任給ランキング` → `製薬・バイオ（製薬・創薬）の初任給ランキング`

## 再発防止（これをやらないと同じことが起きる）

上の対応表は**過去の後始末**であって、原因は残ったままです。

**原因1: URLがスプシのC列そのまま**

`generateStaticParams` がスプシの業界名をそのままURLにしています。
表記を1文字直すだけで、そのURLは死にます。

→ 業界名とURLスラッグを分離し、固定スラッグ表を持つ

**原因2: `/lists/` のスラッグに閾値が入っている**

```ts
// 該当率が50%に最も近い閾値を1つだけ採用する
slug: `${seg.key}--over-${t / 10_000}man`
```

企業を追加して該当率が動くと `t` が変わり、スラッグが変わります。
**スプシを更新するたびに静かに404が増える構造です。**

→ 閾値をURLから外し、`/lists/製薬・バイオ-高初任給` のような固定スラッグにする

ただしこの変更は、**今順位を持っているURLも道連れにします**
（`/lists/外資--over-40man` は 6.4位）。
旧URL全件のリダイレクトが前提になり、一時的な順位低下も起こり得ます。
掲載企業が増えるほど傷が深くなるので、やるなら早いほうがよいと考えます。
